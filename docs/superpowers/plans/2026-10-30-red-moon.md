# Red Moon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a functional offline desktop password manager with an encrypted local vault and a minimal, square-cornered interface.

**Architecture:** A standalone Rust library owns encryption, storage, session state and backup transactions. A narrowly permissioned Tauri 2 adapter connects it to a React interface that receives entry summaries and only explicitly requested secrets.

**Tech Stack:** Rust, RustCrypto Argon2id/XChaCha20-Poly1305, zeroize/secrecy, Tauri 2, React, strict TypeScript, Tailwind, Vitest/Testing Library, native desktop smoke tests.

**Spec:** `docs/superpowers/specs/2026-10-30-red-moon-design.md`

## Global Constraints

- Border-radius zero throughout; minimal flat surfaces and the specified Red Moon palette.
- Offline first launch and operation; no remote fonts, scripts, telemetry, APIs, or plaintext export.
- Argon2id v19, 32-byte key, 16-byte salt, XChaCha20-Poly1305 with a fresh 24-byte nonce per encryption; authenticate the canonical header.
- KDF calibration target roughly 500 ms; floor 64 MiB/three iterations/one lane; ceiling 256 MiB/ten iterations/four lanes for untrusted input.
- Maximum vault file 16 MiB and 10,000 entries; master password 14 characters minimum for creation/change, maximum 1 KiB UTF-8; no normalization.
- Backend inactivity locking defaults to five minutes; copied passwords expire after 20 seconds when clipboard ownership remains verifiable.
- Generated password length 12–128; reject no selected classes and impossible requirements.
- No plaintext disk temporaries, password logs, production developer tools, broad shell/network capabilities, or full-vault frontend caching.
- Windows first; explicitly distinguish Linux validation, Windows-native validation, simulations and unrun checks.
- Use the existing isolated checkout; no worktrees. User-authorized implementation can create source and lockfiles; onboarding scripts must not modify tracked source.

## Review Focus

- Untrusted headers with extreme KDF parameters must be rejected before expensive work (Task 1).
- A second instance and overlapping mutations must never lose an update (Task 2).
- Failure after file replacement must not leave memory pretending an older state is current (Task 2).
- Unlock/reveal responses arriving after lock must not repopulate frontend secrets (Tasks 3 and 5).
- Restore from setup or with a differently passworded backup must validate before replacing any existing vault (Task 2).

## Task 1: Independently testable cryptographic format

**Files:** root `Cargo.toml`, `.gitignore`; `crates/red-moon-core/Cargo.toml`, `src/{lib,error,format,kdf,crypto,model}.rs`, `tests/crypto.rs`; `docs/vault-format.md`.

**Interfaces:** `KdfParams { memory_kib: u32, iterations: u32, lanes: u32 }`; `VaultDocument { entries: Vec<Entry>, settings: Settings }`; `derive_key(password: &SecretString, salt: &[u8;16], params: KdfParams) -> Result<Zeroizing<[u8;32]>>`; `encrypt(document: &VaultDocument, key: &[u8;32], salt: [u8;16], params: KdfParams) -> Result<Vec<u8>>`; `decrypt(bytes: &[u8], password: &SecretString) -> Result<UnlockedVault>`; `UnlockedVault` owns the document, zeroizing key, salt and parameters. `Error` supplies safe public messages without secret interpolation.

- [ ] Check network readiness, install a pinned supported Rust toolchain preserving TLS/signature verification, and check current official crate APIs/RustSec advisories. Pin compatible versions in manifests and lockfile; do not describe blocked checks as passed.
- [ ] Specify the canonical 80-byte header: magic `[u8;8]`, format/cipher/KDF/Argon-version bytes, three little-endian u32 KDF fields, 16-byte salt, 24-byte nonce, little-endian u64 ciphertext length, eight reserved zero bytes. Authenticate all 80 bytes and reject nonzero reserved fields. Document exact constants and payload schema.
- [ ] Write tests `round_trip_unicode`, `wrong_password_rejected`, `tampered_header_rejected`, `tampered_ciphertext_rejected`, `truncation_and_trailing_bytes_rejected`, `kdf_resource_bounds_rejected_before_derivation`, `oversized_payload_rejected`, and `fresh_nonce_each_save`. Assert exact recovered fields, safe failure, and distinct nonce bytes over 1,000 encryptions; use test fixtures with minimum valid production parameters, never silently weaken release parameters.
- [ ] Run `cargo test -p red-moon-core --test crypto`; confirm tests fail because the implementation is absent.
- [ ] Implement bounded decoding, Argon2 calibration, AEAD and zeroizing serialization buffers using the maintained libraries. Model entry fields with opaque random IDs, UTC timestamps, title, username, password, URL, category, tags, notes and favorite; enforce limits before serialization and after decoding.
- [ ] Run crypto tests and `cargo fmt --all --check`; inspect real results and commit the independently tested core.

## Task 2: Transactional storage, backup and password changes

**Files:** `crates/red-moon-core/src/{storage,backup,vault}.rs`, `tests/{storage,backup}.rs`.

**Interfaces:** `Storage::open(path: PathBuf) -> Result<Storage>` owns the exclusive OS lock. `Storage::read() -> Result<Vec<u8>>`; `Storage::commit(bytes: &[u8]) -> Result<CommitOutcome>`; `CommitOutcome` distinguishes committed state from durability uncertainty. `VaultService::{create,unlock,save_entry,delete_entry,change_password,backup,restore}` use storage transactions; caller supplies secrets and user-confirmed paths. `EntryInput` has editable fields only; backend owns IDs/timestamps. `backup(destination: &Path) -> Result<()>`; `restore(source: &Path, backup_password: &SecretString, current_password: Option<&SecretString>) -> Result<()>` validates authentication and preserves an encrypted safety copy before committing.

- [ ] Write storage tests for create/reopen/edit, Unix 0600/0700, lock contention, stale temp handling, symlink rejection and injected failures at write/sync/replace. Assert original vault remains authentic before commit and disk/memory reconciliation after an ambiguous commit.
- [ ] Write backup tests for valid restore, setup-screen restore, wrong backup/current passwords, corrupted/oversized backup, output collision, failed safety-copy creation, failed replacement and master-password changes. Assert failure preserves the prior usable vault and successful password change rejects the old password.
- [ ] Run `cargo test -p red-moon-core --test storage --test backup` to establish failing tests.
- [ ] Implement exclusive random sibling encrypted temps, fsync and platform-specific atomic replacement. Preserve destination on failures, restrict permissions and serialize mutations; use an injectable filesystem fault adapter in tests. Never overwrite a destination backup silently.
- [ ] Implement validated restore and key change with commit-before-memory replacement. Treat copied backups as independent old-password artifacts, and enforce entry count/field limits.
- [ ] Run the two suites, full core tests and `cargo clippy -p red-moon-core --all-targets -- -D warnings`; commit after success.

## Task 3: Session security, password generation and clipboard

**Files:** `crates/red-moon-core/src/{session,generator,clipboard}.rs`, `tests/{session,generator,clipboard}.rs`.

**Interfaces:** `Session<C: Clock>` owns `Option<UnlockedVault>` and an inactivity deadline; `touch`, `lock`, `check_expiry` guard every operation. `GeneratorOptions { length: usize, lowercase: bool, uppercase: bool, digits: bool, symbols: bool }`; `generate(options: &GeneratorOptions) -> Result<SecretString>`. `ClipboardService` wraps a platform clipboard adapter with `copy_password`, `copy_username`, `clear_if_owned` and an incrementing generation token. `EntrySummary` excludes notes/passwords; `EntryDetails` excludes passwords; explicit reveal returns one zeroizing secret.

- [ ] Write fake-clock tests asserting 300-second expiry, no secret operations after expiry, touch extension, manual lock, resume with elapsed inactivity and stale session generation rejection. Add generator tests for bounds, class coverage, empty classes and selection alphabet. Add fake-clipboard tests for 20-second clear, newer content preservation, later app copy and lock cleanup.
- [ ] Run targeted tests to confirm the missing behavior fails.
- [ ] Implement OS-backed unbiased generation; backend password-strength guidance; bounded validated settings and duplicate detection. Keep authentication keys Rust-owned and drop them on lock. Implement generation tokens to reject stale reveal responses after lock.
- [ ] Run `cargo test -p red-moon-core` and clippy; commit after success.
