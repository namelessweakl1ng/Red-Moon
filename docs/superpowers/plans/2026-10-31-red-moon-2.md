# Red Moon 2.0 implementation plan

User requests immediate implementation with no approval prompts. Use existing isolated checkout. Spec: ../specs/2026-10-31-red-moon-2-design.md; full requirements adjacent.

1. Rust core (`model.rs`, `records.rs`, `api.rs`, `vault.rs`, `crypto.rs`, tests/fixtures): test-first encrypted schema2, typed records/checklists, category operations, privacy-safe summaries, legacy Entry compatibility, v1 authenticated migration with preserved encrypted safety file, fresh-install restore, biometric reauthentication/key unlock and stale-key failure. Run core tests/fmt/clippy. Owner core work stream.
2. UI (`android/.../ui/` split components/screens): replace dropdown navigation with Material3 bottom destinations, themed rounded layout, search/filter/recent/favorite/category shortcuts and full typed record/detail/editor/category/settings/recovery flows. Owner UI work stream; use fixed JSON protocol from core.
3. Biometrics (`android/.../security/`): test envelope decoding/bounds/AAD; auth-per-use strong Keystore AES-GCM CryptoObject, private atomic wrapped-key file, invalidation/fallback/cancel, async lifecycle gates. Owner platform work stream; root adds dependencies/Activity callbacks and JNI actions.
4. Root integration (`VaultModel.kt`, `NativeVault.kt`, `MainActivity.kt`, JNI bridge): record snapshots, bounded API key decoding/zeroization, epoch rejection, process-independent locks, Keystore invalidation on credential changes, screen-off protection. No full decrypted vault in Compose state.
5. Backup (`android/.../backup/`): SAF encrypted-only versioned save/import; persisted accurate destination/status/time; verify provider read-back separately from sync; pure Kotlin transfer/gate tests plus manual provider acceptance protocol. Restore independent of old device Keystore; safety copy preserved by core.
6. Verify: core + mobile Rust tests, host realJNI smoke, Kotlin tests/lint, debug APK and instrumentation APK compilation, APK signature/page alignment/permissions, independent full security review and fixes. Run device tests only if connected; report blocked real-provider/biometric verification explicitly. Auto cloud implementation gated on those tests, documented design only in this milestone.

Protocol: list_records returns summaries/categories/settings/generation; record_detail masks secret values, edit_record is explicit full selected fetch, reveal_field reveals one value. save_record/delete_record/favorite_record and save_category/delete_category/reorder_categories perform encrypted transactions. biometric_enroll password reauth returns temporary wrapped-only key to platform; biometric_unlock verifies actual vault AEAD using provided32byte key. Legacy list/save APIs continue preserving newer data.
